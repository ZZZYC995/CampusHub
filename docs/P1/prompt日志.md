2 总体描述

管理员：用户管理、内容审核、违规处理、数据监控、系统配置。

服务端：云服务器、MySQL、Redis、对象存储

兼容：iOS 12+、Android 8+、主流浏览器
2.4 主要功能概览
用户实名注册与身份核验
互助需求分类发布与智能推荐
接单响应与订单流程管理
二手商品发布、浏览、下单
学习 / 运动 / 竞赛组队匹配
在线即时沟通与消息通知

3 具体需求
3.1 功能需求（FR）
3.1.1 用户认证与个人中心
FR-UC-01：系统应支持手机号 + 验证码注册，绑定学号 / 校园身份完成实名核验。
FR-UC-02：系统应支持密码登录、短信快捷登录、第三方授权登录。
FR-UC-03：用户可编辑头像、昵称、学院专业、联系方式、常用地址。
FR-UC-04：系统应展示用户信用分、完成订单数、好评率、认证标签。
FR-UC-05：用户可修改密码、注销账号、设置隐私权限。
3.1.2 互助需求发布与接单
FR-TASK-01：支持按分类发布：快递代取、学习辅导、代排队、物品借用、其他代办。
FR-TASK-02：发布需填写标题、描述、地点、时间要求、报酬、截止时间、图片。
FR-TASK-03：列表按最新 / 距离 / 报酬 / 热度排序，支持关键词筛选。
FR-TASK-04：用户可一键接单，发起沟通，发布方确认接单。
FR-TASK-05：订单状态：待接单→进行中→待确认→已完成→已取消。
FR-TASK-06：支持订单取消、异常申诉、超时自动关闭。
3.1.3 二手交易
FR-TRADE-01：发布二手商品：名称、分类、成色、价格、位置、图片。
FR-TRADE-02：支持收藏、议价、留言、线下交易约定。
FR-TRADE-03：商品可标记已售出，自动下架。
FR-TRADE-04：禁止发布违禁品，系统关键词拦截。
3.1.4 组队匹配
FR-TEAM-01：创建组队：学习、运动、竞赛、社团、出行，填写人数、要求、时间。
FR-TEAM-02：按类型、时间、人数筛选组队，一键申请加入。
FR-TEAM-03：队长可审核成员、解散队伍、群发通知。
FR-TEAM-04：队伍满员自动标记，支持临时调整。
3.1.5 消息与通知
FR-MSG-01：内置 IM 聊天，支持文字、图片、语音片段。
FR-MSG-02：订单状态、接单申请、系统公告实时推送。
FR-MSG-03：未读消息计数，消息置顶与删除。
3.1.6 信用与评价
FR-CREDIT-01：完成互助后双方互评，评分 1-5 星 + 文字评价。
FR-CREDIT-02：信用分由完成率、好评率、违规记录计算。
FR-CREDIT-03：低信用用户限制发布与接单权限。
3.1.7 举报与审核
FR-REPORT-01：用户可举报违规内容、虚假信息、不良行为。
FR-REPORT-02：管理员后台审核需求、商品、评论，可下架 / 封禁。
FR-REPORT-03：违规记录计入用户信用档案。
3.1.8 管理员后台
FR-ADMIN-01：用户管理：查看、禁用、解封、导出数据。
FR-ADMIN-02：内容管理：审核、搜索、批量处理。
FR-ADMIN-03：订单与交易数据统计、活跃用户、热门分类报表。
FR-ADMIN-04：系统公告发布、分类管理、关键词过滤配置。
FR-ADMIN-05：操作日志留存，可追溯查询。
3.2 外部接口需求
3.2.1 用户界面（UI）
UI-01：移动端优先，简洁卡片式布局，浅色主色调。
UI-02：底部导航栏：首页、发布、订单 / 二手、消息、我的。
UI-03：表单必填项标红，提交前校验，错误提示清晰。
UI-04：支持深色模式切换，适配全面屏与平板。
3.2.2 硬件接口
IF-HD-01：调用相机 / 相册上传图片，调用定位获取校内位置。
IF-HD-02：支持消息推送与铃声震动提醒。
3.2.3 软件接口
IF-SW-01：对接第三方短信 API 实现验证码下发。
IF-SW-02：对接第三方支付 API（可选）实现担保交易。
IF-SW-03：对接对象存储服务存储图片与文件。
IF-SW-04：提供开放 API 给校园公众号 / 官网跳转。
3.2.4 通信协议
IF-NET-01：客户端与服务端采用 HTTPS 加密传输。
IF-NET-02：消息采用 WebSocket 实现实时推送。
IF-NET-03：接口遵循 RESTful 规范。
3.3 数据需求
DATA-01：用户数据：学号、手机号、身份信息、头像、信用分。
DATA-02：需求数据：类型、描述、报酬、地点、时间、状态。
DATA-03：订单数据：双方信息、流程记录、评价、申诉记录。
DATA-04：商品数据：分类、价格、图片、发布人、状态。
DATA-05：消息数据：聊天记录、通知记录、留存 90 天。
DATA-06：日志数据：操作日志、登录日志、审核日志，留存 1 年。
3.4 性能需求（NFR-PER）
NFR-PER-01：支持单校在线用户≥5000 人，并发≥500。
NFR-PER-02：页面加载≤2s，列表查询≤1s，详情加载≤1.5s。
NFR-PER-03：消息推送延迟≤3s。
NFR-PER-04：系统全年可用率≥99.5%，单次故障恢复≤30min。
NFR-PER-05：图片上传失败率≤0.1%。
3.5 安全需求（NFR-SEC）
NFR-SEC-01：用户密码加密存储，禁止明文传输。
NFR-SEC-02：实名信息脱敏展示，仅后台可见。
NFR-SEC-03：接口防刷、限流、防 SQL 注入与 XSS 攻击。
NFR-SEC-04：违规关键词实时过滤，敏感内容自动拦截。
NFR-SEC-05：管理员操作双因子验证，日志不可篡改。
NFR-SEC-06：聊天内容不涉及违法信息，保留举报追溯能力。
3.6 设计约束（NFR-CON）
NFR-CON-01：仅面向本校在校学生，禁止校外用户注册。
NFR-CON-02：不提供现金提现，仅支持信息撮合。
NFR-CON-03：遵循校园网络安全规范，不存储敏感隐私数据。
NFR-CON-04：前端兼容主流移动端浏览器与小程序。
NFR-CON-05：数据库每日自动备份，保留 7 天备份。
3.7 软件质量属性（NFR-QA）
可用性：新手引导≤3 步，核心功能 3 步内完成。
可维护性：模块低耦合，分类与规则可配置化。
可扩展性：支持新增互助分类、新增举报类型。
兼容性：跨端一致，无功能差异。
易用性：适老化简化操作，错误可一键回退。
3.8 其他需求
支持多语言切换（中文简体 / 英文）。
提供用户使用手册与常见问题 FAQ。
支持意见反馈与客服工单。
定期数据导出与合规审计。
