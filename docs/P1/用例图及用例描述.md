## 3.2 核心用例描述
**用例1：发布互助需求**  
角色：普通用户  
前置条件：  
用户已登录平台  
用户已完成学号实名认证  
用户账号未被封禁  
基本流：  
用户点击 “发布互助需求”  
选择需求类型  
填写需求描述、报酬、截止时间、特殊要求  
提交发布  
系统校验内容合法、必填项完整  
需求发布成功，状态为 “待接单”  
替代流：  
4a：必填项未填写 → 系统提示 “请完善信息”，不予发布  
4b：内容包含违规词 → 系统拦截并提示 “内容不合法”  
后置条件：  
需求成功进入待接单列表  
其他用户可查看并承接该需求

**用例2：承接互助需求**  
角色：接单用户  
前置条件：  
用户已登录并完成学号认证  
目标需求处于 “待接单” 状态  
接单用户账号状态正常  
基本流：  
用户浏览待接单列表  
选择目标需求，点击 “承接任务”   
系统确认需求未被承接、信息合法   
承接成功，订单状态改为 “进行中”  
系统开启双方私聊通道  
替代流：  
3a：需求已被他人承接 → 提示 “任务已被接单”  
3b：用户试图承接自己发布的需求 → 提示 “不能承接自己的任务”  
后置条件：  
订单状态变为 “进行中”  
双方可进行站内沟通

**用例3：双方评价**  
角色：普通用户、接单用户  
前置条件：  
互助任务已标记 “完成”  
未超过评价有效期（7天）  
基本流：  
用户进入订单详情页  
点击 “去评价”  
选择1–5星并填写评价内容  
提交评价  
系统展示评价并更新对方信用分  
替代流：  
3a：超时未评价 → 系统自动给出 5 星默认好评  
3b：评价包含违规内容 → 系统屏蔽并提示用户  
后置条件：  
评价成功展示在对方主页  
信用分计算完成
