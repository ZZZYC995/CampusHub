# 1 引言
## 1.1 目的
本文档用于明确CampusHub校园互助平台的功能与非功能需求，作为开发、测试、验收的依据，并记录需求来源与人工修正内容。

## 1.2 范围
平台面向本校在校学生，提供跑腿代取、二手交易、学习辅导、资料分享、失物招领、组队搭子、咨询问答、站内交流等核心互助服务。

## 1.3 定义
委托方：发布互助需求的用户
承接方：接单提供帮助的用户
信用分：用户行为与履约情况的评价指标
托管机制：平台暂存报酬，任务完成后结算
学号认证：确保用户为本校学生的实名方式

## 1.4 参考文献
IEEE 830 需求规格说明书标准
P1 阶段任务说明
用户调研问卷与访谈原始数据
AI生成需求规格说明书

# 2 总体描述
## 2.1 产品视角
CampusHub 是一个校内安全可信的互助交易平台，解决传统互助无保障、无约束、信息杂乱的问题。

## 2.2 用户特征
本校本科生/研究生
年龄18–25岁
熟悉移动端操作
重视安全、隐私、履约保障

## 2.3 约束
仅面向本校学生，需实名认证
不对接校方系统、不使用校园卡
必须保护用户隐私，不泄露学号/手机号

## 2.4 假设
用户均为真实在校学生
用户愿意遵守平台规则
用户可接受积分/小额现金作为酬劳

# 3 功能需求
## 3.1 用户认证模块
3.1.1 用户可通过学号完成实名注册，确保仅本校学生可进入平台。  
优先级：Must  
来源：人工补充

3.1.2 用户手机号脱敏显示，仅展示后四位，保护隐私。  
优先级：Must  
来源：人工补充

3.1.3 用户手机号脱敏显示，仅展示后四位，保护隐私。  
优先级：Must  
来源：人工补充

## 3.2 互助发布与接单模块
3.2.1 用户可发布跑腿、咨询、辅导、代拿等互助需求，填写内容、报酬、要求、截止时间。  
优先级：Must  
来源：AI生成+人工修改  
修改说明：AI未限定校内场景与截止时间，人工补充校内属性与时效约束。

3.2.2 承接方接单前需确认任务规则，委托方可查看承接方信用分。  
优先级：Must  
来源：AI生成+人工修改  
修改说明：AI 未提及信用分，人工根据调研添加。

## 3.3 二手交易模块
3.3.1 用户可发布二手物品，支持图片、描述、价格、分类。  
优先级：Should  
来源：AI生成

3.3.2 交易支持平台托管，买家确认后再打款给卖家。  
优先级：Must  
来源：人工补充

## 3.4 失物招领模块
3.4.1 用户可发布失物/拾物信息，支持描述、时间、地点、联系方式（脱敏）。  
优先级：Should  
来源：AI生成+人工修改  
修改说明：人工补充隐私保护要求。

## 3.5 学习与资料模块
3.5.1 用户可分享学习资料、笔记、课件，支持分类查看。  
优先级：Should  
来源：AI生成

3.5.2 支持按学科/课程筛选资料。  
优先级：Could  
来源：人工补充

## 3.6 组队搭子模块
3.6.1 用户可发布课程组队、活动拼车、竞赛组队等需求。  
优先级：Should  
来源：AI生成+人工修改  
修改说明：AI 泛化生成，人工限定为校内真实高频场景。

## 3.7 交流与社区模块
3.7.1 平台内置私聊/对话功能，不依赖QQ/微信。  
优先级：Should  
来源：人工补充

3.7.2 支持帖子分类、标签、搜索。  
优先级：Could  
来源：人工补充

## 3.8 信用与评价模块
3.8.1 任务完成后双方可互相评分与评价。  
优先级：Must  
来源：AI生成

3.8.2 违规用户将被降低信用分，影响接单/发布权限。  
优先级：Must  
来源：人工补充

## 3.9 举报与仲裁模块
3.9.1 用户可对违规、欺诈、不良言论进行举报。  
优先级：Must  
来源：AI生成

3.9.2 平台管理员可处理纠纷、进行仲裁。  
优先级：Must  
来源：人工补充

## 3.10 任务完成判定模块
3.10.1 任务完成以委托方确认为主，支持上传凭证。  
优先级：Must  
来源：人工补充

3.10.2 超时未确认则自动判定完成。  
优先级：Should  
来源：人工补充

## 3.11 游客访问模块
3.11.1 未登录游客可浏览平台公开内容，但无法发布/接单。  
优先级：Could  
来源：人工补充

# 4 非功能需求
## 4.1 性能需求
4.1.1 页面加载≤2秒。  
优先级：Must  
来源：AI生成

4.1.2 支持同时在线500+用户无卡顿。  
优先级：Should  
来源：人工补充

## 4.2 安全性需求
4.2.1 用户实名信息加密存储，不对外泄露。  
优先级：Must  
来源：人工补充

4.2.2 禁止不良内容、违规交易、欺诈行为。  
优先级：Must  
来源：AI生成+人工修改  
修改说明：人工明确校内场景的违规定义。

## 4.3 可用性需求
4.3.1 界面简洁、操作步骤少，新手 3 分钟内上手。  
优先级：Must  
来源：人工补充

4.3.2 支持移动端、简易网页端访问。  
优先级：Should  
来源：AI生成

## 4.4 可维护性需求
4.4.1 支持管理员后台审核、封禁、公告发布。  
优先级：Must  
来源：AI生成+人工修改  
修改说明：人工补充校内管理实际需要。
